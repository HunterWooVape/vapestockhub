# 后台录入配套：已确认方案

确认日期：2026-10-21。分类：MVP+ Optimization。

## 已确认的六项

1. 表单按产品资料、库存明细、库存说明、发布设置组织；参数与内部信息按需展开。
2. 草稿允许缺项。发布要求标题、品牌、产品类型、一张真实主图、正整数总量；市场、仓库、说明、补充参数等选填。型号独立填写；按已填资料推荐标题，候选由人选择，可手动修改，之后不自动覆盖。价格由人填写，可为空；MOQ 可为空且不默认成 1，单数值与公开显示开关分开，默认不公开。区间与特殊条件填公开库存说明。
3. 文字、粘贴的 Excel 表格和清单图片进入同一整理预览。图片采用本机 OCR，不调用外部大模型。相同配置、浓度与完全同名口味合计；不同规格分开。以明细合计为准，原总计差异提醒。未识别内容保留供人工修正，核对后应用。
4. 核对后的库存明细、公开说明、产品参数分别保存。原始截图、原始文字、附件及内部备注不进入公开数据。初期由用户本地保存原始材料，浏览器识别输入不随草稿保存。旧记录兼容，打开编辑页不自动写库或改总量。
5. 编辑内容可在正式详情布局预览；价格、MOQ 与空值按同一公开规则展示。预览不会发布，不触发联系追踪。最后由人执行发布。
6. 用 LOST ANGEL MATE 50K Kit 与 HYPPE INFINITI 50K 真实资料验证草稿流程，记录实际问题后整理短 SOP；稳定后再考虑 skill。真实库存不自动发布。

## 实施与验收

- 复用现有草稿编辑与角色校验；不接入暂缓的外部模型及飞书功能。
- 新字段与公开视图同时适配；新增记录默认独立内容格式。旧记录保留原链接、原值、原 MOQ 可见性。
- 公开入口在数据库层屏蔽隐藏价格、隐藏 MOQ 与新格式的旧混合描述，不能只在页面上隐藏。
- 检查草稿缺项、发布校验、重复行、规格隔离、原总量差异、隐藏信息、预览与正式布局一致性。
- 图片识别效果以真实样本为准，数字和口味必须人工核对。实现参考：[Tesseract.js API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md)、[本地资源配置](https://github.com/naptha/tesseract.js/blob/master/docs/local-installation.md)。

本地实现与两款清单验证已完成首轮：存在需要人工修正的 OCR 错字与漏行，已确认人工核对后可完成明细整理、预览与草稿保存。操作简表见 `docs/INVENTORY_ENTRY_SOP.md`。发布与配套迁移状态以交付记录为准。
